# Subscription AI providers: Claude Code and Codex

## Overview

Add two providers to Settings → AI → "Add AI model": **Claude Code (subscription)** and **Codex (ChatGPT subscription)**. Each lets the instance owner sign in from inside MoneyMatter ("Sign in with Claude" / "Sign in with ChatGPT" opens the real login page), pick a supported model, and then run every AI feature that resolves a user connection (categorization, statement parser including images and PDFs, investment transactions import, invoice matching) on their own subscription instead of a per-token API key.

Out of scope: **budget suggestions**. `services/budget-plans/suggested-lines-ai.ts` (`pickModels`, lines ~213–224) builds its specs only from server keys (`getServerApiKey`) under its own daily cap and calls `createProviderModel` directly; it never reads user connections, so it can't run on a CLI connection without a separate design. No task touches that file.

The backend never implements an OAuth client. It drives the unmodified CLIs:

- Claude: `claude setup-token` in a PTY → authorization URL → user pastes the code back → one-year OAuth token → stored encrypted → runs use `CLAUDE_CODE_OAUTH_TOKEN`.
- Codex: `codex login --device-auth` in a private `CODEX_HOME` → verification URL + one-time code → CLI finishes → `auth.json` stored encrypted → runs materialize it into a private `CODEX_HOME`.

Availability: self-hosted instances only (`IS_SELF_HOST=true`), instance admins only (`ADMIN_USERS`). Personal use only, per Anthropic's and OpenAI's subscription terms.

## Solution Overview

1. **Thin in-repo providers.** `services/ai/cli/claude-code-language-model.ts` and `codex-language-model.ts` implement `LanguageModelV3` (`doGenerate`; `doStream` wraps `doGenerate` as one text chunk) by spawning the pinned CLI once per call with a scrubbed environment and an empty temp working directory. Failures become `APICallError`s carrying synthetic HTTP statuses (401 auth, 404 model, 429 subscription limit, 503 overloaded, 502 any other failed run), each with a JSON body,, so the existing classifiers and feature switches keep working.
2. **Login orchestration.** `services/ai/cli/login/` runs the CLI login in a `node-pty` PTY, parses the URL/code, and keeps an in-memory session (owner, provider, state, encrypted credential) with a 15-minute TTL.
3. **Storage and credential freshness.** The credential (Claude token or Codex `auth.json`) is encrypted with the existing `encryptToken` into the connection's `keyEncrypted`. No model, probe or logout call site holds a decrypted CLI credential value; a decrypted stored credential exists only between `source.load()` and the end of one `runWithCliCredential` call. Models, probes and logout get a **credential source** `{ connectionKey, load, save? }` and every CLI invocation that uses a stored or session credential goes through one helper, `runWithCliCredential` (Task 3). It takes the per-connection slot, then calls `load()` (fresh DB read + decrypt), then runs; for Codex it materializes `auth.json` into a fresh private `CODEX_HOME` (dir 0700, file 0600) and, in a `finally` whenever the file's hash changed (success or failure), re-encrypts it through `save()` before releasing the slot and removing the directory.
4. **Gating.** `GET /availability` is behind `authenticateSession` only and answers with a reason; the four auth-session endpoints are behind `selfHostOnly` + `adminOnly`; `assertCliAiAllowed({ userId })` on create/update/test of CLI connections and on every run in the resolver.
5. **UI.** Two presets in the Add dialog; in place of API key/base URL fields they show a sign-in panel, a curated model list and a personal-use notice. The connection row shows the credential state, a "Sign in again" action and Disconnect.

**Endpoints** (under `/user/settings/ai/cli`, all behind `authenticateSession`):
| Method | Path | Gate | Body | Returns |
|---|---|---|---|---|
| GET | `/availability` | `authenticateSession` only (no `selfHostOnly`, no `adminOnly`) | – | 200 `CliAiAvailability` for every signed-in user, cloud included; `available:false` with `reason` `not-self-host` (cloud), `admin-not-configured` (`ADMIN_USERS` empty), `not-admin` |
| POST | `/auth-sessions` | `selfHostOnly, adminOnly` | `{ provider }` | `CliAuthSessionInfo` once the URL is parsed (≤30 s) |
| GET | `/auth-sessions/:id` | `selfHostOnly, adminOnly` | – | `CliAuthSessionInfo` (frontend polls every 2 s) |
| POST | `/auth-sessions/:id/code` | `selfHostOnly, adminOnly` | `{ code }` (Claude only, 1–500 chars, printable, no control chars) | `CliAuthSessionInfo` |
| DELETE | `/auth-sessions/:id` | `selfHostOnly, adminOnly` | – | 204, kills the PTY |

"Cloud → 404" (from `selfHostOnly`) and "non-admin → 401" (from `adminOnly`) apply only to the four `/auth-sessions` endpoints; `/availability` never answers 404 or 401 for a signed-in user.

Create/re-auth reuse the existing `POST /settings/ai/connections` and `PUT /settings/ai/connections/:id` with `cliAuthSessionId`; Test (`POST /settings/ai/connections/test`) takes it too. Session rules: must be `succeeded`, owned by the caller, same provider. **Test never consumes the session** (it reads it with `peekCredential`); create/PUT consume it only after their probe succeeded, so a failed probe (wrong model) leaves the session usable for a retry, and Test-then-Save with one session id works. A consumed session id is refused (422). One live session per user per provider (a new start cancels the old one); at most 3 PTYs instance-wide.

**PTY matching rule (both logins)**: a URL, token or device code is accepted only once it is followed by a delimiter that has actually arrived in the buffer: whitespace (space, `\r`, `\n`) or the PTY's exit (end of stream counts as a delimiter). Each pattern ends in a lookahead for that, e.g. `https://\S*oauth\S*(?=\s)`, and `waitFor` re-runs the match on the whole rolling buffer after every chunk, so a chunk boundary inside a field never yields a prefix.

**Claude login (PTY)**: `node-pty` spawn of `<claude> setup-token`, `cols: 1000` so nothing wraps, env from the builder with `HOME`/`CLAUDE_CONFIG_DIR` = fresh temp dir and `BROWSER=/bin/true`. Strip ANSI, match the first delimited `https://\S*oauth\S*(?=\s)` URL → `awaiting-user`. On code submit, write `code + '\r'`, state `verifying`, then match a delimited `sk-ant-oat\w*-[A-Za-z0-9_-]{20,}(?=\s)` (or the same token at end of stream on exit) within 60 s → encrypt, `succeeded`, kill PTY, remove temp dir. Any other exit → `failed` with the last 5 screen lines (token pattern redacted). Raw PTY output is never logged.

**Codex login (PTY)**: `<codex> login --device-auth -c cli_auth_credentials_store="file"` with `CODEX_HOME` = fresh 0700 temp dir. Match the first delimited `https://\S+(?=\s)` URL and a delimited code `\b[A-Z0-9]{4,}-[A-Z0-9]{4,}(?=\s)` → `awaiting-user` with both. Wait for exit (≤15 min): exit 0 and `auth.json` present → read, encrypt, `succeeded`; remove the dir.

**Claude runtime**: `<claude> -p --input-format stream-json --output-format stream-json --verbose --model <m> --system-prompt <system> --tools "" --setting-sources "" --strict-mcp-config --no-session-persistence --max-turns 3 [--json-schema <schema>]`, cwd = empty temp dir, stdin = one `{"type":"user","message":{role,content}}` line with text and base64 `image` blocks. Read the final `{"type":"result"}` event: `structured_output` (JSON-stringified as the text) or `result`, `usage` → `inputTokens/outputTokens`, `is_error` / `api_error_status` → mapped error. Strip `format` keywords from the schema before sending (the AI SDK still validates against the Zod schema). Fail closed on tools, with one exception: when `--json-schema` was passed, exactly one `tool_use` block named `StructuredOutput` is allowed (the CLI's own structured-output mechanism, see Context). Any other `tool_use` block, a `StructuredOutput` block on a run without `--json-schema`, or a second `StructuredOutput` block in the same run kills the process group and fails the call with a synthetic 502 (`cli_tool_use_blocked`). A schema run whose `result` event lacks `structured_output` fails as 502 (`cli_failed`); the `StructuredOutput` block's own `input` is never used as the answer, only the `result` event's `structured_output`.

**Codex runtime**: `<codex> exec --json --ephemeral --ignore-user-config --ignore-rules --skip-git-repo-check -s read-only -c approval_policy="never" -c cli_auth_credentials_store="file" -c web_search="disabled" -c shell_environment_policy.inherit="none" <CODEX_TOOL_DISABLE_ARGS> -m <m> -C <tmp> -o <tmp>/last.txt [--output-schema <tmp>/schema.json] [-i <tmp>/img-N.<ext>…] -`, stdin = system prompt + user text (Codex has no system-prompt flag; verify `developer_instructions` in the pinned version and prefer it if present). Text = `last.txt`; usage from `turn.completed`; `error`/`turn.failed` events → mapped error. Schema gets `additionalProperties: false` on every object.

`CODEX_TOOL_DISABLE_ARGS` is one exported constant in `codex-language-model.ts`: `--disable <name>` for each of `shell_tool`, `unified_exec`, `unified_exec_tty`, `shell_snapshot`, `apps`, `plugins`, `remote_plugin`, `plugin_sharing`, `browser_use`, `browser_use_external`, `browser_use_full_cdp_access`, `computer_use`, `in_app_browser`, `multi_agent`, `view_image`, `image_generation`, `hooks`, `skill_search`, `skill_mcp_dependency_install`, `tool_suggest`, `tool_call_mcp_elicitation`, `sleep_tool`, `code_mode_host`, `goals`, `realtime_conversation`, `workspace_dependencies`, `worktrees` (the list verified against 0.160.1 in Context; `view_image` is the model's tool for reading local files, attachments passed with `-i` don't need it). Because `--disable` rejects unknown names, a CLI bump that renames a feature fails loudly at the first run and in Task 11's gate instead of silently re-enabling a tool. `unified_exec` cannot be switched off on 0.160.1 (Context), so the adapter also fails closed: any `--json` `item.*` event whose item type is not on the allowlist `agent_message`, `reasoning`, `error` (an `error` item goes through the error mapping; so `command_execution`, `mcp_tool_call`, `web_search`, `file_change`, `todo_list` and anything new) kills the process group and fails the call with a synthetic 502 (`cli_tool_use_blocked`, JSON body) before the run can finish. When bumping Codex, rerun `codex features list` under an empty `CODEX_HOME` with these args and update the list until no tool-related feature reads `true` except `unified_exec`.

**Environment builder** (`cli-env.ts`): the child env is built from scratch, never spread from `process.env`: `PATH`, `LANG`, `TZ`, `SSL_CERT_FILE`/`NODE_EXTRA_CA_CERTS` if set, `HOME`, then provider vars (`CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CONFIG_DIR`, `DISABLE_AUTOUPDATER=1`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`; or `CODEX_HOME`, `RUST_LOG=error`). `ANTHROPIC_*`, `OPENAI_*`, DB and app secrets are therefore absent from the child's own environment, so billing can't silently fall back to the operator's API key. This is environment isolation only: the CLI runs as the backend's uid and could read `/proc/1/environ`, other `CODEX_HOME`s or attachments if it executed commands. Keeping secrets away from the model rests on the tool hardening (Claude `--tools ""` plus fail-closed `tool_use` with only the schema-gated `StructuredOutput` exception; Codex `CODEX_TOOL_DISABLE_ARGS` plus fail-closed tool items), not on the env builder.

**Limits**: `cli-run-limiter.ts` runs one CLI call per connection at a time and at most `AI_CLI_MAX_CONCURRENT_RUNS` (default 2) instance-wide. Two clocks: the caller's `abortSignal` bounds the whole call including the queue wait, and a run timeout (`CLI_RUN_TIMEOUT_MS` = 5 min for feature runs, 90 s for validation probes, 5 s for logout) is created **inside** `runWithCliSlot` when the slot is acquired and combined with the caller's signal (`AbortSignal.any`) for the spawned process. `aiCallGuards` CLI arm: `AbortSignal.timeout(30 min)` as the queue-plus-run ceiling, `maxRetries: 0`. Probes on a stored connection wait at most 2 min for the slot; a wait that runs out throws `CliSlotBusyError`, which the probe reports as `ai.cliConnectionBusy` ("A run on this connection is in progress, try again in a minute") without recording a verdict. Abort kills the child process group (SIGTERM, SIGKILL after 5 s).

**Error mapping** (`cli-errors.ts`): every synthetic error is an `APICallError` with url `cli://<provider>`, a synthetic `statusCode` and a JSON `responseBody` `{"error":{"type":"<code>","message":"…"}}` (JSON, so `isNonApiResponseError` never reads it as `endpoint-down`). Auth (`401`, `isRetryable: false`): "not logged in", "invalid_grant", "OAuth token has expired", `authentication_failed`, exit after a 401; limit (`429`): "usage limit", "rate limit", `usage_limit_reached`, "Claude AI usage limit reached|<epoch>" (reset time parsed into the message); model (`404`, type `model_not_found`): "model … not supported/not found"; overloaded (`503`, type `overloaded`): `api_error_status` 529 or 503, `overloaded_error`, "Overloaded"; any other non-zero exit or unparseable output → `502` (type `cli_failed`, `temporary` at feature runs; the validation probe treats it as invalid, see Task 7), and a blocked tool → `502` (type `cli_tool_use_blocked`, same treatment). Spawn `ENOENT` is the one error without a status: `CliNotInstalledError`, a subclass of `APICallError` with no `statusCode` (`isRetryable: false`, url `cli://<provider>`, `cause` = the spawn error with `code === 'ENOENT'`, own `name = 'CliNotInstalledError'`, `provider` field), detected by `isCliNotInstalledError({ error })` (unwraps `RetryError`, checks `instanceof`). Because it is a status-less `APICallError`, `isConnectionError` classifies it as `endpoint-down` with no classifier change (a plain `Error` would land in `unknown`), so it is the **only** CLI `endpoint-down` that reaches the user-fixable branch; aborts and timeouts on CLI providers also classify as `endpoint-down` but stay `temporary` (see below).

**Failure routing** (`connection-failure.ts`): `isUserFixableEndpointDown({ provider, error })` = `provider === custom || isCliNotInstalledError({ error })`. The two downgrade sites switch from `provider !== AI_PROVIDER.custom` to `!isUserFixableEndpointDown(...)`, and their comments are rewritten to say so: `categorization-service.ts:222-225` and `ai-extraction-failure.ts:44-51`. `markCustomEndpointUnreachable` becomes `markEndpointUnreachable` (callers: `categorization-service.ts:91`, `ai-extraction-failure.ts:63`, the `services/ai/index.ts` re-export) and picks the copy: custom → today's copy, CLI → "The <Claude Code|Codex> CLI is not installed in the backend image". Subscription copy: `markConnectionRejected` says "Sign in again in Settings → AI" for CLI providers, `describeRateLimited({ aiClient, cause })` names the subscription limit and its reset time. Validation probe (CLI arm): `CliNotInstalledError` → invalid with the not-installed copy; other `endpoint-down` (probe timeout) keeps today's `ai.connectionProviderUnreachable`.

**Credential sources and `runWithCliCredential`** (`services/ai/cli/cli-credential-run.ts`):

- `CliCredentialSource = { connectionKey: string; load: () => Promise<{ credential: string; revision: string }>; save?: ({ credential, loadedRevision }) => Promise<void> }`. `revision` is the ciphertext `load()` decrypted (`encryptToken` uses a random IV, so every write yields a new ciphertext and equality is a sound version check); `runWithCliCredential` hands the revision it loaded back to `save`, so every write-back is a compare-and-swap against the credential the run started from.
- `connectionCredentialSource({ userId, connectionId })` (in `ai-connections.ts`): `connectionKey = connection id`; `load` reads the row fresh (`readStoredConnections`) and decrypts `keyEncrypted` (throws the existing unreadable-key error if missing); `save` = `replaceConnectionCredential({ userId, connectionId, expectedKeyEncrypted: loadedRevision, keyEncrypted: encryptToken(credential) })` through `mutateConnections` with `onMissing: 'skip'` (a connection deleted mid-run is not resurrected). Inside `mutate` it is a compare-and-swap: it writes only when the locked row's `keyEncrypted` still equals `expectedKeyEncrypted`; otherwise it changes nothing and logs at warn level (`connectionId`, no key material). Runs and probes on one connection are serialized by its slot, so a mismatch means a write outside the slot replaced the credential mid-run (a re-auth PUT, whose probe holds the `session:<id>` slot, not this one), and the newer credential wins.
- `sessionCredentialSource({ userId, sessionId, provider })` (in `cli-auth-sessions.ts`): `connectionKey = 'session:' + sessionId`; `load` = `peekCredential` (returns the session's current encrypted credential as `revision`); `save` = `replaceSessionCredential({ userId, sessionId, expectedRevision: loadedRevision, credential })`, the same compare-and-swap against the session's stored ciphertext, which also skips (warn log) a session that was consumed, cancelled or expired meanwhile.
- `runWithCliCredential({ provider, source, abortSignal, timeoutMs, run: ({ credential, codexHome?, signal }) })`: `runWithCliSlot` (key = `source.connectionKey`) → start the run timeout → `{ credential, revision } = await source.load()` → Claude: `run({ credential, signal })`; Codex: `withCodexHome({ authJson: credential, run, onRefreshed: source.save })`, whose `finally` hashes `auth.json` and calls `onRefreshed` (→ `source.save({ credential, loadedRevision: revision })`) when it differs from the loaded content, whether `run` resolved or threw (a refresh followed by a 429, a timeout or a process-group kill is still persisted). A `save` failure is logged at error level and a compare-and-swap miss at warn level; the run's own error, if any, is what propagates. An optional `beforeRelease({ outcome })` callback runs after `save` while the slot is still held (create/PUT use it to consume the session, Task 7). The slot is released only after `save` and `beforeRelease` finished.
- Callers, and the only way any of them reaches a CLI with a credential: both language models' `doGenerate` (every call, so one model instance reused across categorization batches loads the latest credential each time), the CLI arm of `validateConnection` (create/update/test probes), and the delete-time `codex logout`.

**Display**: `toCatalogKey` maps `claude-code/<id>` → `anthropic/<catalogId>` and `codex/<id>` → `openai/<catalogId>`; `getModelProfile` forces `pricing: null` for CLI providers; `resolveFeatureStatus` sets `billing: 'subscription'`. Capabilities keep `pdf` because the backend turns PDFs into text or page images for these providers.

## Decisions taken without the owner

1. **Thin in-repo providers instead of the community packages.** Evaluated `ai-sdk-provider-claude-code@3.6.1` and `ai-sdk-provider-codex-cli@1.5.0`, the `ai-sdk-v6` dist-tags; `latest` (4.3.3 / 2.3.0) target `@ai-sdk/provider` v4 = AI SDK v7. Both handle images and structured output, but: the Claude package runs through `@anthropic-ai/claude-agent-sdk@0.3.283`, which bundles a 225 MB native Claude Code 2.1.283 binary (a second copy beside the CLI the image needs for `setup-token`) and talks a stdio control protocol that can't be faked at the process boundary for e2e; it silently drops PDF file parts; its env allowlist forwards every `ANTHROPIC_*` var (an operator `ANTHROPIC_API_KEY` would outrank the OAuth token and bill the API). The Codex package spreads the whole `process.env` (DB credentials, `APPLICATION_JWT_SECRET`) into the child. A ~300-line in-repo adapter per CLI gives full control of env, flags and error mapping, and is testable with fake binaries.
2. **CLI versions**: `@anthropic-ai/claude-code@2.1.292` (current `stable` dist-tag) and `@openai/codex@0.160.1` (the version on the owner's Mac, above the 0.156 floor the community provider documents for current GPT models). Installed globally with `npm install -g` in the production image, not as backend dependencies; `node-pty@1.1.0` is the only new runtime dependency.
3. **PTY for both logins** (`node-pty`): `setup-token` is an Ink TUI that needs a TTY; Codex uses the same runner for uniformity.
4. **Codex credential at rest = encrypted in the DB**, not a volume: `auth.json` is encrypted into `keyEncrypted` like API keys, written to a private temp `CODEX_HOME` only for the length of one run, written back re-encrypted (in a `finally`, success or failure) when Codex refreshes it, then deleted. This gives encryption at rest and needs no new compose volume. Refresh tokens may be single-use, so correctness rests on three rules, not just serialization: every invocation that uses the stored credential (runs, test/update probes, logout) goes through `runWithCliCredential`; the credential is loaded inside the per-connection slot, never captured earlier; `updateConnection` never writes back a `keyEncrypted` it read before its probe; and every refresh write-back (`replaceConnectionCredential`, `replaceSessionCredential`) is a compare-and-swap against the ciphertext the run loaded, so a run that started before a re-auth can't overwrite the new credential.
5. **Gate** = `isSelfHost() && isAdminUsername(username)`, checked at the four auth-session endpoints (`selfHostOnly` + `adminOnly`), at create/update/test, and on every run. `GET /availability` is the exception: `authenticateSession` only, so it can report why the feature is unavailable (`not-self-host`, `admin-not-configured`, `not-admin`) instead of answering 404/401. Self-hosters must set `ADMIN_USERS`; docs and the UI say so. A user removed from `ADMIN_USERS` keeps the connection, but runs refuse with a clear message.
6. **Login sessions live in memory** (single backend process on self-host); a restart drops in-flight sign-ins and the user starts again.
7. **Static curated model list** in shared types plus free-text entry; the create/test probe confirms the model. Neither CLI has a reliable unauthenticated model list (`codex app-server` model listing needs auth and another process).
8. **Cost display**: new `AIFeatureStatus.billing`; the UI shows "Included in your subscription" in place of a per-100-rows price. Usage tokens are still tracked.
9. **Concurrency**: 1 run per connection, 2 per instance (each CLI process takes ~200–400 MB RSS); run timeouts (5 min per run, 90 s for the validation probe) start when the slot is acquired, so queue time behind a long categorization batch doesn't eat them; a 30-min caller ceiling bounds queue + run; no SDK retries.
10. **Subscription errors** surface through the existing classifiers via synthetic HTTP statuses (with JSON bodies), so no feature switch gains a new case; the copy differs, and the two `endpoint-down` downgrade guards change from "not custom" to `!isUserFixableEndpointDown(...)` so a missing CLI (and only that) reaches the connection-flagging branch while CLI aborts and timeouts stay temporary.
11. **PDFs** to CLI providers go as extracted text or rendered page images (the existing custom-provider branch in `extract-invoice.service.ts`, generalized to "provider can't take PDF file parts").
12. **Hardening**: no tools, no settings/MCP/plugins, no session persistence, empty temp cwd, scrubbed env; Codex runs read-only, ephemeral, ignoring user config and rules, with every agent tool feature disabled explicitly (`CODEX_TOOL_DISABLE_ARGS`, web search off, `shell_environment_policy.inherit="none"`), because read-only sandboxing still allows reading files and running commands. Both adapters fail closed on any tool event in the output stream (Claude's one exception: a single `StructuredOutput` call on a run that passed `--json-schema`, which is how the CLI delivers structured output and executes nothing), which covers `unified_exec` (not switchable on 0.160.1) and tools a future CLI version adds. Untrusted document content (invoice PDFs, statement images) reaches the model, so this is what stops a prompt injection from reading `/proc/1/environ`, other homes or attachments under the backend's uid.
13. **Disconnect** = delete the connection. Codex: best-effort `codex logout` through `runWithCliCredential` (slot held, freshest credential, 5 s run timeout) first, to revoke the tokens. Claude has no CLI revoke, so the confirm dialog links to claude.ai settings for revoking the token.
14. **Claude token expiry**: `credentialExpiresAt = now + 365 days` at sign-in (docs: one-year token). The row shows it and turns into a warning 14 days before.
15. **Restored backups**: CLI connections come back invalid with no key (existing behavior), so the owner signs in again; no special-casing.
16. **Test seam**: CLI paths via `AI_CLI_CLAUDE_PATH`/`AI_CLI_CODEX_PATH`; `MM_FAKE_CLI_SCENARIO`, `MM_FAKE_CLI_RESPONSE_FILE` (canned answers per run, mirroring the MSW mocks' `categorizations`/`rawText`) and `MM_FAKE_CLI_STATE_DIR` are forwarded to children only under `NODE_ENV=test`.
17. **Popup blockers**: the click handler opens a blank tab synchronously and points it at the URL once the backend returns it; a visible "Open sign-in page" link is always shown as a fallback.
18. **Visibility**: non-admins and cloud never see the two presets; an admin on self-host whose image lacks a CLI sees the preset disabled with the reason. The frontend fetches availability on self-host for every signed-in user and lets the endpoint decide; `not-self-host`/`not-admin`/`admin-not-configured` are not shown in the UI (they serve API clients, tests and support).
19. **UI/docs copy**: "For your own personal use with your own subscription, under Anthropic's / OpenAI's terms"; the Codex panel tells the user to turn on device code login in ChatGPT → Settings → Security first.
